# Mnemon 技能市场/更新与自进化辨析 + 最终确认清单

## 背景与关联
承接文档 `cb6bd015-c45f-4de5-9dc2-7aba240248a2`（存储范围 vs 记忆空间范围、三空间方案）与 `6ace19f3-6258-4eda-b7ec-4060e9c0c156`（项目档案范围 / 用户画像范围 / 主动记录 / 技能管理）。用户（通信工程研究生，涉及课题组项目与学校课程）继续追问：想让电脑上的 skill 更新、能否用自进化代替手动下载；以及三空间与范围设置里"哪个留默认"。以下为源码/locale 核对结论与面向该用户的建议，均为推荐方案，用户未明确确认已实际应用。

## 自进化 ≠ 自动下载/更新技能文件（关键概念澄清）
- 自进化（`skills.evolution` / `evolutionHint`）：后台复盘对话 → 提出**技能内容改进建议**。官方文案："会話をレビューしてスキルの更新を提案します。タスクセッションはローカルに保持されます"（复盘对话、提出技能更新建议；任务会话本地留存）。
  - 它复盘的是**用户的对话历史**（发现"反复纠正同一件事""以后都这样做"这类模式），起草一份改进版 SKILL.md，与当前版本回测打分后由用户决定是否采纳。
  - **它不联网、不检查新版本、不替用户下载任何东西。**
  - 默认只提建议、不自动采纳（`skills.autoAdopt`「自动采纳新建议」默认关，且需开启自动回测、仅在文本用例零退步时采纳、最多重试 2 次）。不会偷偷改坏技能。
  - 代价：每轮对话后额外 token/算力（任务 Agent 复盘+起草+回测）、本地留存复盘读过的对话（机密已替换）、持续积压待处理建议需打理（`skills.statusOn`「自进化已开启 · {waiting} 项待处理」）。
- 真正与"获取/更新技能文件"相关的是**技能管理 → 市场与目录**（locale `skills.groupSources`「市场与目录」、`skills.market`「市场来源」、`skills.marketHint`「管理技能市场目录与索引源」）：
  - `skills.marketRefresh`「更新」/ `skills.marketRefreshing`「更新中…」= 手动刷新市场索引，看有没有新版本。
  - 市场来源（截图显示 2/2）从 skills.sh、GitHub 等索引搜索并安装技能——**需用户手动点安装/更新**。
  - `skills.allowLinkedUpdates`「允许更新链接技能」：官方提示"更新将直接写回符号链接目标并影响共享 Agent，仅对可信目录启用" → 保持关（会写穿共享技能文件）。
  - 结论：官方**没有**"自动检查并下载技能更新"功能；自进化干不了这事，市场来源也只是目录。想更新技能就去市场手动点更新。
- 给该用户的建议：别为"不手动下载技能"去开自进化（动机不成立）；其核心目标"记住研究生科研/课程事实"靠记忆空间而非技能管理。技能管理全部保持默认（自进化关、链接更新关）。

## "哪个留默认"——四个范围下拉最终清单
| 设置项 | 值 | 是否改 |
|---|---|---|
| 存储范围 | 集中存储·按工作区隔离 | 留默认（不动） |
| 记忆空间范围 | global：所有工作区共用 | 改 |
| 项目档案范围 | 跟随存储范围（默认） | 留默认（不动） |
| 用户画像范围 | 全局共享 | 改 |
- 三个记忆空间（个人与通用 / 课题组科研 / 课程学习）没有"默认"一说：三个平等、都要建，Provider 选 Mnemon Native、建完逐一激活；Agent 按描述自动路由（详见 cb6bd015）。
- 核心动作只有三件：改两个"范围"下拉（记忆空间范围、用户画像范围 → 全局共享）+ 建 3 个记忆空间并激活；项目档案无需预建库；其余所有开关（主动记录、技能管理、运行时记忆实验性开关）保持默认/现状。
